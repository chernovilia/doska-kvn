# Структура проекта

Как устроен код: репозитории, папки, модули, модели данных и основные сценарии. Что именно сейчас работает — [STATE.md](STATE.md), все эндпоинты — [API.md](API.md).

## Репозитории

| Репозиторий | Что внутри | Где крутится |
|---|---|---|
| [`doska-kvn`](https://github.com/chernovilia/doska-kvn) (папка `доска:квн`) | Сайт: Next.js 14 (App Router), Tailwind, Framer Motion, lucide-react. Здесь же вся документация (`documents/`) | Amvera → `доска-квн.рф` |
| [`doska-kvn-api`](https://github.com/chernovilia/doska-kvn-api) | API: NestJS 10, Prisma 5, PostgreSQL 17 | Amvera → `api.доска-квн.рф/v1` |

Внешние сервисы: Timeweb S3 (фото), Unisender Go (письма), Cloudflare (только DNS).

```
Браузер ──► доска-квн.рф (Next.js, SSR + клиент)
   │            │ SSR: fetch в API (для /ad/[id] — с cookie посетителя)
   └──────────► api.доска-квн.рф/v1 (NestJS) ──► PostgreSQL
                     ├──► Timeweb S3 (фото)
                     └──► Unisender Go (коды входа, письма-уведомления)
```

Авторизация — httpOnly-cookies `access_token` / `refresh_token` на общем домене `.доска-квн.рф`, поэтому их получают и сайт (SSR), и API.

## API (`doska-kvn-api`)

### Модули `src/`
| Модуль | Что делает |
|---|---|
| `auth` | Вход по коду, JWT, `/me`; `JwtAuthGuard`, `OptionalJwtAuthGuard`; письма (`email-template`, `unisender-go.sender`); `blocked.ts` — запрет действий заблокированным; `admin-check.ts` — кто админ |
| `ads` | Лента (фильтры, ранжирование, `searchText`), объявление, создание и правка, просмотры, подъём, архив/продление, жалобы, «мои объявления»; `lifecycle.service.ts` — сроки и чистка фото раз в час/сутки; `sections.ts` — список разделов |
| `uploads` | Загрузка фото: sharp → WebP → S3 |
| `chats` | Диалоги и сообщения, письмо на первое непрочитанное, пуш на каждое; `unread.ts` — счётчик непрочитанного |
| `favorites` | Избранное |
| `reviews` | Отзывы: право оставить, создание, пересчёт рейтинга |
| `notifications` | `notify()` — запись для колокольчика + пуш + письмо; список, прочитано. Глобальный модуль |
| `push` | Web Push (VAPID): ключ, подписки, `sendToUser()`; удаляет мёртвые подписки. Глобальный модуль |
| `pwa` | Метрики приложения: `/app/open`, `/app/event` |
| `settings` | Чтение настроек из `Setting`: числа (`read-settings.ts`), JSON — соседи и контакты (`json-settings.ts`) |
| `support` | Обращения в поддержку: пользователь и админ |
| `users` | Публичный профиль продавца, свой адрес (`username.ts` — правила и зарезервированные слова) |
| `admin` | Метрики, модерация, пользователи и блокировка, жалобы, отзывы, поддержка, настройки. `AdminGuard` |
| `regions`, `health`, `seed`, `prisma` | Регионы и города, `GET /site` (соседи, контакты), проверка живости, начальные данные и настройки, клиент БД |
| `app-throttler.guard.ts`, `guest-id.ts` | Лимиты запросов: по аккаунту, e-mail (коды входа) или cookie гостя `gid` — не по IP |

При старте: `prisma db push` (безопасные изменения), сид справочников и недостающих настроек (значения, изменённые в админке, не перезаписываются), заполнение `Ad.searchText` и `Ad.publishedAt` у старых объявлений.

## Основные сценарии

### Подача и модерация
1. Фото грузятся по 3 параллельно в `POST /uploads/ad-photo` ещё на шаге «Фото».
2. `POST /ads` → статус по `moderation.autoApprove`: `approved` (сразу в ленте, `publishedAt = сейчас`) или `pending` (админам уведомление).
3. Админ: одобрить / отклонить с причиной / скрыть опубликованное / вернуть / удалить — автору уведомление и письмо.
4. Неопубликованное видит только автор (плашка статуса с причиной) и админы.

### Лента
`GET /ads` → фильтры (место, раздел или «даром», подгруппа, цена, характеристики, поиск по `searchText`) → ранжирование `computeScore` + правила (VIP, не больше N объявлений автора в топ-10) → выдача. Подробно — [RANKING-AND-PROMO.md](RANKING-AND-PROMO.md), раздел 0.

### Связь продавца и покупателя
«Написать» → `POST /conversations` (диалог на пару объявление + покупатель) → `/messages?chat=`. Когда каждый написал 4 сообщения и прошёл час — у обоих «Оцените собеседника».

### Уведомления
Любой модуль вызывает `NotificationsService.notify(userId, …)`: запись для колокольчика + пуш на все подписки пользователя + письмо, если включена почта. Пуш и письмо уходят фоном — сбой не ломает действие. Когда показывать окно установки и предложение пушей — `components/AppShell.jsx`, подробности — [STATE.md](STATE.md).

### Поддержка
`/help` → `POST /support` (админам уведомление) → админ отвечает в «Поддержка» → пользователю уведомление и письмо → переписка продолжается в `/help`.
