## Известные проблемы и ограничения

### 🟡 Скорость первого запроса

**Симптом**: TTFB на пустом кеше ~1.5-2 сек.

**Причина**: TLS handshake через Amvera ingress = ~1.2 сек. После включения Cloudflare Proxy 🟠 на `api.` — должно упасть до ~200-400 мс.

**Проверить**: ещё раз замерить после того, как CF Proxy на api-сабдомене прогреется (10-15 мин после включения).

**Долгосрочно**: перейти на Next.js Server Components + SSR, чтобы fetch к API происходил на серверной стороне Amvera (внутренняя сеть = 0 задержка).

### 🟡 Prisma migrate deploy падает на Amvera CNPG

**Симптом**: `permission denied to create database`.

**Workaround**: используем `prisma db push --accept-data-loss` — работает.

**Долгосрочно** (перед этапом 3): дать пользователю `chernov97` привилегию `CREATEDB` через Superuser, чтобы вернуть normal migration flow:
```sql
ALTER USER chernov97 CREATEDB;
```

### 🟡 Repo public

**Пока ок**: секретов в коде нет.

**Перевести в приватные** обязательно до этапа 3 (SMS-авторизации с ключами).

### 🟡 Автоматическое обновление Let's Encrypt vs Cloudflare Proxy

**Сценарий**: Amvera обновляет cert каждые ~60 дней через HTTP-01 challenge. Если в момент обновления Proxy включён — обновление упадёт, сайт скажет «expired».

**Митигация**: раз в 2 месяца временно выключать Proxy на день, либо перейти на Cloudflare Universal SSL (тогда CF сам выдаёт cert).

**Задача**: настроить UptimeRobot алерт на expired cert, чтобы не пропустить.

### 🟡 Нет мониторинга ошибок

**Симптом**: если сервер выкинет 500 — узнаем только по жалобе от юзера.

**Решение**: подключить Sentry (бесплатный тариф до 5k ошибок/мес) — этап 3.

## Аудит безопасности

### 🟢 Что защищено

- HTTPS везде, HSTS через Cloudflare
- CORS whitelist на API (только наш домен)
- helmet middleware на API
- ValidationPipe на всех DTO
- Секреты (DATABASE_URL, superuser password) в Amvera env, не в коде
- IP БД не торчит наружу (только внутренний Amvera-хост `.rw`)

### 🔴 Что требует внимания

- **Тестовая auth через X-Debug-User-Id** — заменить на JWT (этап 3)
- **Публичные repo** — приватизировать до этапа 3
- **Rate limiting отсутствует** — добавить с Redis (этап 4)
- **npm vulnerabilities**: 25 на бэке (6 low, 8 med, 11 high) — прогнать `npm audit fix` + Dependabot
- **Next.js 14.2.5 security vulnerability** — обновить до 14.2.30
