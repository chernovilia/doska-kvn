## 1. Ранкинг объявлений — формула

Место в схеме: `src/ads/ads.service.ts` → `computeScore(ad, weights)`.

```
score = 
    freshness  × 0.35    ← свежесть (доминирует)
  + promo      × 0.30    ← купленное продвижение
  + trust      × 0.15    ← доверие к автору
  + quality    × 0.10    ← фото + описание
  + engagement × 0.10    ← активность юзеров
  + boost bonus (0.15)   ← если жал «Поднять» за 24ч
```

### Компоненты

| Компонент | Формула | Что даёт |
|---|---|---|
| **freshness** | `max(0, 1 − часы_с_публикации / 240)` | 1 в первый час, 0.5 на 5-й день, 0 после 10 дней |
| **promo** | `promoLevel / 4` | 0 / 0.25 / 0.5 / 0.75 / 1 (VIP) |
| **trust** | `(verified ? 0.5 : 0) + rating/10` | 0 → 0.98 |
| **quality** | `(есть_фото ? 0.5 : 0) + (описание>50 симв ? 0.5 : 0)` | Легко получить 1.0 |
| **engagement** | `min(1, views/100)*0.5 + min(1, writes/10)*0.5` | Растёт от активности |
| **boost** | `+0.15` если `boostedAt < 24 ч назад` | Одноразовый пинок |

**Максимальный score** ≈ 1.15. **Минимальный** ≈ 0.10.

### Правила поверх формулы

1. **VIP в топе**: первые N позиций (по умолчанию 3) — только VIP объявления
2. **Anti-repetition**: один автор ≤ 3 карточек в топ-10 (иначе магазин заспамит)

### Всё настраивается из БД без деплоя

Ключи в таблице `Setting`:

```
ranking.weight.freshness      = 0.35
ranking.weight.promo          = 0.30
ranking.weight.trust          = 0.15
ranking.weight.quality        = 0.10
ranking.weight.engagement     = 0.10
ranking.freshness_days        = 10
ranking.vip_top_positions     = 3
ranking.same_author_max_top10 = 3
ranking.boost_bonus           = 0.15
```

## 2. Сценарии (что происходит в разных случаях)

### Свежее объявление новичка

Иван зарегистрировался, опубликовал диван с 3 фото и описанием.

```
freshness = 1.00 × 0.35 = 0.350
quality   = 1.00 × 0.10 = 0.100
────────────────────────
score = 0.450
```

### Через 5 дней — если ничего не делать

```
freshness = 0.50 × 0.35 = 0.175
quality   = 0.100
────────────────────────
score = 0.275   (упал на 40%)
```

### Через 10 дней

```
freshness = 0
score = 0.100   (на дне, где-то на 5-6 странице)
```

### Иван на 5-й день нажал «Поднять»

```
freshness = 0.175
quality   = 0.100
boost     = 0.150
────────────────────────
score = 0.425   (почти вернулся к первому дню)
```

### Проверенный магазин с рейтингом 4.8

```
freshness = 0.350
trust     = (0.5 + 0.48) × 0.15 = 0.147
quality   = 0.100
────────────────────────
score = 0.597   (сразу выше новичка)
```

### VIP-платное объявление магазина

```
freshness = 0.350
promo     = 1.00 × 0.30 = 0.300
trust     = 0.147
quality   = 0.100
────────────────────────
score = 0.897   (топ ленты + гарантия топ-3)
```

## 3. Как работает промо по scope

Ключевой принцип: **VIP покупается на объявление + scope**, а не глобально.

### Модель scope (нужно добавить в `AdPromo`)

```prisma
model AdPromo {
  ...existing fields...

  // Где промо работает — «место»
  placeScope     String?    // 'city' | 'region' | 'agglomeration' | null (везде)
  placeValue     String?    // 'vyksa' | 'kvn' | null

  // Где промо работает — «категория»
  categoryScope  String?    // 'section' | 'category' | null (все)
  categoryValue  String?    // 'market' | 'диваны' | null

  // Ротация внутри VIP-мест
  rotationSeed   Int?       // случайное число для round-robin
}
```

### Слои цен (индикативные)

| Scope | Пример | Индикативная цена | Аудитория |
|---|---|---|---|
| Категория + Город | Диваны Выксы | 300 ₽/нед | Локальный магазин |
| Раздел + Город | Все товары Выксы | 500 ₽/нед | Магазин с ассортиментом |
| Категория + Агломерация | Диваны КВН | 700 ₽/нед | Специализированный |
| Город (весь) | Всё в Выксе | 900 ₽/нед | Крупный магазин |
| Раздел + Агломерация | Все товары КВН | 1500 ₽/нед | Сеть магазинов |
| Агломерация | Везде в КВН | 3000 ₽/нед | Топовые бренды |

**Принцип**: шире scope → выше цена → больше охват.

### Логика применения VIP при рендере ленты

Юзер зашёл на `/vyksa?section=market&chip=Диваны`:

```
VIP #1: placeValue=vyksa, categoryValue=диваны
  → 100% попадание, топ-3

VIP #2: placeValue=vyksa, categoryValue=null (все категории Выксы)
  → 100% попадание, топ-3

VIP #3: placeValue=kvn (агломерация), categoryValue=market
  → попадание (Выкса ⊂ КВН, Диваны ⊂ Товары), топ-3

VIP #4: placeValue=navashino
  → НЕ попадает

VIP #5: categoryValue=услуги
  → НЕ попадает
```

## 4. VIP-переполнение — что если купили больше чем мест

Проблема: `vip_top_positions=3`, а VIP-объявлений подходящих под scope — 5+.

### Выбранное решение — ротация (гибрид A + D)

**Механика:**
1. Все активные VIP последних 7 дней получают **равные показы в топ-3** через round-robin по `rotationSeed`
2. Внутри одного «поколения» — новый VIP выше старого (по свежести покупки)
3. Через 7 дней VIP-статус остывает, promo-бонус в `computeScore` продолжает работать (но VIP-плашки уже нет)

**Плюсы:**
- Все VIP получают одинаковое время в топ — честно
- Новичок не проигрывает старому магазину
- Не нужен аукцион (сложная логика)

**Альтернативы, которые отбросили:**
- Аукцион цен → сложно, пугает малый бизнес
- Свежесть → VIP-старик через 3 дня бессмысленен
- Лимит слотов → отпугивает клиентов «извините, всё продано»

### Ключ Setting для настройки

```
promo.vip_rotation = 'random' | 'freshness' | 'round-robin'
promo.vip_lifetime_days = 7
```

## 5. Настраиваемая агломерация — уже почти готово

### Что уже есть в схеме

```prisma
model Region {
  id        String   @id
  name      String
  neighbors String[]     // ← массив id соседних регионов
  launched  Boolean  @default(false)
  ...
}

model City {
  id       String  @id
  regionId String       // ← город принадлежит региону
  ...
}
```

### Текущий сид (уже в БД)

```
kvn:      neighbors = [murom, arzamas, pavlovo]
murom:    neighbors = [kvn]
arzamas:  neighbors = [kvn, pavlovo]
pavlovo:  neighbors = [kvn, arzamas]
sarov:    neighbors = [arzamas]

Города:
  kulebaki, vyksa, navashino → regionId=kvn
  murom → regionId=murom
  arzamas → regionId=arzamas
  ...
```

### Что уже работает

При открытии `/vyksa` фронт делает 3 запроса параллельно:
1. Основная лента: `place=vyksa`
2. **«В соседних городах»**: `place=kvn` (регион Выксы), filter cityId≠vyksa
3. **«Другие регионы»**: по одному ad из каждого neighbor Kvn

Это уже реализовано в `lib/api.js` → `getAds({ includeNearby: true })`.

### Что осталось написать (управление из админки)

1. **Endpoints:**
   - `GET /admin/regions` — список регионов с кол-вом объявлений
   - `PATCH /admin/regions/:id` — { name, neighbors[], launched }
   - `PATCH /admin/cities/:id` — { regionId } (перенос города в другой регион)

2. **UI в /admin**:
   - Новая вкладка «Регионы»
   - Список регионов, для каждого — соседи (чипсами добавлять/удалять)
   - Тумблер «Запущен» (`Region.launched`)
   - Внутри региона — список городов

### Сценарий расширения — «муромские города в КВН»

**Вариант A: муром отдельный регион, но связан**
```
Region.neighbors: муром ↔ kvn
Городов не переносим
→ Муром показывается в «Другие регионы» на /kvn
```

**Вариант B: муромские города становятся частью КВН**
```
City.regionId для муромских городов = 'kvn'
Region.id='murom' помечаем launched=false (или удаляем)
→ Города Мурома в основной ленте /kvn как равноправные
```

Выбор — по бизнес-логике. Обычно **вариант A** — сохранение регионов как отдельных.

## 6. Виртуальные звёзды — геймификация на MVP

**Wallet-модель уже есть**: `User.wallet.balance` (int, копейки/звёзды), `WalletTransaction` (история).

### Начисления (bonus за активность)

```
+10 ⭐ — прохождение онбординга
+5  ⭐ — первое опубликованное объявление
+3  ⭐ — загрузка 3+ фото в объявлении
+1  ⭐ — за каждое активное объявление в конце недели
+5  ⭐ — подтверждение телефона (когда будет)
+2  ⭐ — первый ответ покупателю (когда чаты)
+1  ⭐ — сессия > 5 мин (daily bonus, 1 раз в сутки)
```

### Списания (что покупают)

```
-5  ⭐ — бонусный «Поднять» без cooldown
-15 ⭐ — «Подсветить» объявление (highlight, жёлтая рамка)
-30 ⭐ — «Срочно» (urgent, красная плашка)
-50 ⭐ — VIP на 24 часа в своей категории города
```

**Цель**: научить пользователя механике буста/промо, не тратя реальные деньги. Когда включим платные варианты — юзер уже знает ценность.

## 7. Дорожная карта по монетизации

### Сейчас — до запуска
Всё бесплатно. Инфраструктура готова.

### Месяц 1-3 после запуска — сбор аудитории
- Кнопка «Поднять» бесплатно раз в 3 дня (все юзеры)
- Начисление звёзд за активность
- Расход звёзд на бусты/выделения
- **Никакой оплаты реальными деньгами**

### Месяц 4-6 — первая монетизация
- **Тариф Бизнес** для магазинов: 500 ₽/мес
  - До 100 активных объявлений
  - Автобуст всех объявлений раз в 3 дня
  - Бейдж «Магазин»
  - Приоритет модерации
- ЮKassa для приёма платежей
- Платный «Быстрый буст» без cooldown — 30 ₽

### Месяц 7+ — расширение
- VIP по scope (город / регион / агломерация × раздел / категория)
- Ротация внутри VIP
- Автопродление подписок
- Кабинет продавца с аналитикой
- Пакеты звёзд для покупки (100 ⭐ = 100 ₽)

## 8. Лимиты юзеров — «сколько бесплатно»

Все — через `Setting`, меняются из админки.

| Ключ | Дефолт | Что делает |
|---|---|---|
| `limits.maxActiveAdsPerUser` | 10 | Максимум активных объявлений |
| `limits.maxAdsPerMonth` | 30 | Максимум публикаций в месяц |
| `limits.bumpCooldownHours` | 72 | Cooldown между ручными бустами |
| `limits.adTtlDays` | 30 | Через сколько уходит в архив |
| `limits.photosPerAd` | 6 | Максимум фото в объявлении |
| `limits.dailyLoginBonus` | 1 | Звёзд за сессию > 5 мин раз в сутки |

Плюс уже прошитые в throttler:
- 5 объявлений/час, 20/сутки на IP (антиспам)
- 30 фото/час, 100/сутки

## 9. Модерация — три уровня, идём эволюционно

### Сейчас (auto — по умолчанию)
```
Публикация → immediately approved
```

### Опция ручной модерации (уже готова)
Тумблер `Setting['moderation.autoApprove'] = false`:
```
Публикация → status: pending
Админ смотрит в /admin → превью → Одобрить / Отклонить
```

### Будущее (ИИ-модерация)

**Дубликаты одного автора** — pHash фото + text similarity:
```prisma
model AdPhoto {
  phash String?    // ← уже есть в схеме!
}
```
Реализация: 2-3 часа. Не требует LLM.

**Проверка контента через LLM** (GigaChat / YandexGPT):
```
Публикация → 
  ├─ pHash-проверка дубликатов (мгновенно)
  ├─ LLM-модерация (2-5 сек)
  └─ результат:
      ├─ PASS → approved
      ├─ ORANGE → pending (ручная)
      └─ RED → rejected + reason
```

Планируется на месяц 4+.

## Резюме одним абзацем

Ранкинг работает на 6 сигналах, где свежесть доминирует (35%), а платное продвижение — вторая сила (30%). Trust к автору сейчас минимальный (нет отзывов и верификации), но он уже учитывается — как только появятся данные, ранкинг сам их подхватит. VIP покупается на объявление с указанием scope (город/регион/агломерация × раздел/категория), при переполнении применяется ротация. Настройки — через `Setting` в БД, меняются из админки без деплоя. Инфраструктура для монетизации на 90% готова в схеме — осталось написать endpoints и UI, но это делаем не раньше 4-го месяца, чтобы дать аудитории вырасти.
