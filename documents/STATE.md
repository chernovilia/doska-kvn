## ✅ Что работает в проде

### Инфраструктура
- **Фронт**: Next.js 14 (App Router) на Amvera, `доска-квн.рф`
- **API**: NestJS 10 + Prisma 5 на Amvera, `api.доска-квн.рф/v1`
- **БД**: PostgreSQL 17 (Amvera CNPG, внутренний host `amvera-chernovilia-cnpg-doska-kvn-db-rw`). Локаль базы — `C`: `ILIKE` и `lower()` не складывают кириллицу, поэтому поиск идёт по `Ad.searchText` (см. «Поиск»)
- **Медиа**: Timeweb S3 (`doska-kvn-main`, path-style, ACL public-read)
- **Почта**: Unisender Go (транзакционный API, `noreply@доска-квн.рф`, DKIM/SPF/DMARC)
- **DNS**: Cloudflare, записи в режиме «только DNS» (прокси выключен 28.09) — трафик идёт напрямую на Amvera, сертификаты выпускает Amvera
- **Деплой**: push в `main` → Amvera собирает и перезапускает. API при старте делает `prisma db push` (только безопасные изменения), заполняет служебные поля (`searchText`, `publishedAt`) и досевает недостающие настройки

### Авторизация и онбординг
- Вход по email: 6-значный код (`/auth/email/request` → `/verify`), повтор не чаще раза в 60 с, 5 попыток
- JWT: access 15 мин + refresh 90 дней в httpOnly-cookies с `Domain=.xn----7sbhf4acwc1a.xn--p1ai`; refresh ротируется, отозванные — в `RefreshToken.revokedAt`
- Клиент: `AuthProvider` (`lib/auth.js`), кеш `doska-kvn:me` в sessionStorage применяется после монтирования (иначе ломается гидрация)
- `/onboarding` — страница (не модалка: во встроенных браузерах панели перекрывают фиксированные окна). `AuthOnboardingGate` уводит туда, пока `me.onboardedAt === null`. Поля: имя, город, способ связи, уведомления на почту
- `?returnTo=` — только внутренние пути (`safeReturnTo` в `lib/site.js`)

### Лента и поиск
- На компьютере: без баннеров-карусели (вернём с настройкой в админке, `components/HeroBanner.jsx`), «+ Подать объявление» в шапке
- «В соседних городах» (выбран город): превью, тап по блоку — вся лента региона. Соседи города — из админки (Настройки → «Соседние города»), по умолчанию — остальные города региона и запущенные соседние регионы
- Подвал (компьютер): разделы, города, контакты из админки (Настройки → «Контакты в подвале»)
- Шапка (закреплена сверху): логотип, место текстом с булавкой, колокольчик, вход/аватар; поиск с пристыкованной «Найти»
- Разделы: 14 настоящих (с 1.1.0 добавлены «Продукты», «Для бизнеса», «Бюро находок»; около 60 подгрупп и 300 категорий) + виртуальный «Отдам даром» (цена 0 в разделах с вещами и животными). Плитки под шапкой, первая — «Ещё» (каталог разделов с подгруппами). У выбранного раздела — лента подгрупп
- Фильтры в URL: `?section=&group=&q=&sort=&pmin=&pmax=&attr=`. Переключаются через `history.pushState` без запроса страницы; «назад» возвращает прошлый фильтр
- Сортировка иконкой (рекомендуемые / новые / дешевле / дороже), «Цена ▾» (от–до), «Фильтры» по характеристикам раздела
- По умолчанию — «Все объявления» места по рейтингу (см. [RANKING-AND-PROMO.md](RANKING-AND-PROMO.md), раздел 0)
- **Поиск**: `Ad.searchText` — заголовок, описание, адрес, категория и характеристики в нижнем регистре, `ё → е`. Ищет без учёта регистра по кириллице независимо от локали БД
- Место, которого нет в БД (соседние регионы), даёт пустую выдачу, а не всю доску

### Карточка и страница объявления
- Карточка: квадратное фото, цена, заголовок, сводка характеристик, «город · время», счётчик фото, без фото — иконка раздела. Вся карточка — ссылка, кнопки рядом (не вложены)
- Страница: галерея свайпом со счётчиком, цена, путь «раздел › подгруппа › категория», место, время, просмотры, характеристики, описание, продавец (со ссылкой на его страницу), похожие
- На телефоне снизу панель «Позвонить / Написать» (позвонить — если продавец выбрал телефон; номер только вошедшим)
- Просмотры: `POST /ads/:id/view`, раз в сутки на зрителя, автор не считается
- **Неопубликованные** (на проверке, отклонённые, скрытые) видит только автор и админы: SSR ходит в API с cookie посетителя. У автора сверху плашка статуса с причиной и ссылкой в поддержку; «Поделиться» и «Написать» скрыты

### Подача объявления
- `PostAdModal`, 7 шагов: город → раздел → категория → характеристики → описание и цена → фото → проверка. Шапка с шагами закреплена; город, раздел и категория — переход по тапу
- Фото: выбрать сразу несколько, грузятся по 3 параллельно с превью и спиннером; порядок — долгим тапом и перетаскиванием (первое — обложка); на проверке — миниатюры
- Цена по разделу: вилка зарплаты у вакансий, «₽ в месяц / за сутки» у аренды; без цены — «Даром» у вещей, «Договорная» у услуг
- Афиша: обязательные дата и время (по Москве) и место; у жилья — адрес или район
- **Правка**: карандаш на карточке в профиле и «Редактировать» на странице объявления → та же форма, заполненная, к любому шагу — тапом по номеру. Модерация как при подаче; отклонённое и скрытое после правки — всегда на проверку
- Итог зависит от статуса из ответа API: «Объявление опубликовано» или «Отправлено на проверку» (при выключенной автопубликации)

### Модерация
- Автопубликация — переключатель в админке (`moderation.autoApprove`). Выключена → объявление `pending`, админам уведомление и письмо
- Статусы: `pending` → `approved` | `rejected`; `approved` → `hidden` (скрыть из ленты и поиска); `hidden` | `rejected` → `approved` («вернуть в ленту», дата публикации сохраняется)
- Каждый переход — уведомление автору с причиной (на сайте и письмом)
- «Мои объявления» в профиле: вкладки Активные · На проверке · Отклонённые · Архив

### Срок показа и архив
- Опубликованное показывается 60 дней, за 3 дня — уведомление «Продлить»; потом архив. Автор может сам убрать в архив («Продано») и вернуть в ленту
- Архив удаляется через 90 дней, отклонённые — через 30 (с предупреждением за 3 дня). Все сроки — в админке; проверка раз в час (`AdLifecycleService`, см. [API.md](API.md))

### Подъём и рейтинг
- Новое объявление после публикации сутки получает бонус — встаёт наверх с учётом рейтинга
- **Автоподнятие** (необязательно): переключатель «Поднимать автоматически» на шаге «Проверка» при подаче и на странице продвижения — объявление поднимается само, когда наступает срок подъёма. Общий выключатель — в админке («Автоподнятие доступно»)
- «🚀 Продвинуть» под своим объявлением → `/promote?ad=…`: «Поднять в ленте» (бесплатно, раз в 10 дней — настройка в админке; до этого «Поднять можно через N дн.»), «Срочно», «Выделить цветом», «В топе раздела» — «скоро»
- Вкладка «Продвижение» в профиле (оранжевая, с ракетой): варианты и список опубликованных
- Все веса и сроки — в админке → «Настройки»

### Характеристики
- Поля по разделу и подгруппе — `data/attributes.js`, хранятся в `Ad.attributes` (JSONB), меняются без миграций
- Марка, модель, бренд, порода — выбор из списка с поиском (`type: 'combo'`, справочники в `data/brands.js`): 67 марок авто и около 500 моделей, мото и коммерческий транспорт, шины, 27 брендов телефонов с моделями, компьютеры, ТВ, приставки, бытовая техника, породы кошек и собак. Ищется и по-русски («лада», «киа», «айфон»); вписанное руками приводится к строке из списка; чего нет в списке — остаётся как ввели. Модель зависит от марки. По этим полям работает фильтр в ленте. В «Бюро находок» цена — это вознаграждение, без неё на карточке «Потеряно» / «Найдено»

### Сообщения

### Избранное, продавец, отзывы
- Сердечко в карточке и на странице (`lib/favorites.js`, общий набор id на вкладку). Страница `/favorites`, в нижнем меню и в шапке на компьютере
- `/user/[id]` — страница продавца: имя, город, оценки, «на Доске с», «о себе», объявления, отзывы
- Отзыв — из переписки, когда каждый написал ≥ 4 сообщений и с первого прошёл час (настройка в админке); обоим в чате плашка «Оцените собеседника». 1–5 звёзд и текст; один на диалог от каждого. Рейтинг пересчитывается

### Уведомления
- Колокольчик: счётчик раз в минуту, список при открытии, тап — прочитано и переход
- События: объявление опубликовано / отклонено / скрыто / удалено / снова в ленте / скоро в архив / в архиве / скоро удалим, новый отзыв, ответ поддержки; админам — объявление на модерации, новое обращение

### Помощь

### Приложение (PWA) и уведомления
- Иконка «Д/» (`public/icons`, `app/icon.png`, `app/apple-icon.png`), манифест `app/manifest.js`, service worker `public/sw.js` — только пуши и счётчик на иконке, страницы не кэшируются
- Окно «Установите приложение!» (`InstallGuide`, шапка закреплена): шаги под платформу и браузер — iOS (Safari, Chrome, ВК), Chrome (кнопка «Установить»), Яндекс, Samsung, встроенные браузеры (→ «Открыть в браузере»), компьютер. Показ: после каждого опубликованного или отправленного на проверку объявления (при любом закрытии окна «Готово», в т. ч. жестом «назад») и на каждый второй заход (через 8 с; заход — после 30+ минут без активности, в т. ч. возвращение в открытую вкладку; переходы по сайту таймер не сбрасывают); «Не показывать» или крестик — пауза (14 дней, настраивается) для обоих; всегда — Настройки → «Установить приложение». Уже установленным не показываем
- Пуши (Web Push, VAPID в env API): на каждое уведомление и сообщение в чате; предложение включить — после первого сообщения за заход (не чаще раза в 14 дней), а у установленного приложения — и после публикации; на iPhone в браузере вместо предложения — окно установки. Переключатель — Настройки → Уведомления
- Когда предлагаем включить пуши (с 1.1.1): при открытии установленного приложения вошедшим пользователем (`app.push.on_app_open`); после первого сообщения за заход; после публикации — в том числе следом за окном установки; полоса над списком в «Сообщениях», пока пуши выключены (на iPhone в браузере — предложение установить). Пауза `app.push.ask_every_days` ставится только по «Не сейчас»; закрыли окно — спросим в следующий заход
- Экран диалога при открытой клавиатуре (`app/messages/page.jsx`): пока клавиатура открыта, iPhone отдаёт жест не списку, а всему экрану (экран дёргается, список стоит) — поэтому жест по списку забираем целиком и двигаем список сами, с инерцией (с 1.1.2); клавиатура закрыта — штатная прокрутка, у края сдвиг на 1px. Касания шапки и панели ввода экран не двигают (`preventPagePan`), поле ввода не трогаем. К последнему сообщению возвращаем, только если человек был внизу
- **Правила показа и тексты окна — в админке**: Настройки → «Приложение и уведомления» (включено ли, после публикации, каждый N-й заход, перерыв для нового захода, задержка, пауза после «Не показывать», баннер, предложения уведомлений, тексты). Доходят до телефонов через `GET /site` за 5 минут. Паузу ставят только «Не показывать» и крестик у окна, появившегося само; тап мимо окна и окно, открытое вручную, паузу не ставят
- **Баннер «Установите приложение!»** вверху страниц (`InstallBanner`), закреплён над шапками (высота — в CSS-переменной `--banner-h`): иконка, заголовок, «Установить», крестик. Виден, пока сайт не установлен; крестик прячет на срок паузы. Нет на входе, онбординге, в админке, чате, правилах
- **Диагностика `/app-status`** (ссылка в админке): почему окно на этом устройстве показывается или нет, номер захода, паузы, состояние уведомлений; кнопки «Показать окно», «Включить уведомления», «Сбросить показы на этом устройстве»
- Счётчик непрочитанных на иконке (`setAppBadge`)
- Метрики: открытие с иконки / appinstalled → `AppDevice`, воронка → `AppEventDaily`; админка → Обзор → «Приложение»
- Свой адрес профиля `/u/<адрес>` (таблица `UserHandle`), старый `/user/<id>` переадресует

### Фото
- `POST /uploads/ad-photo`: sharp — поворот по EXIF, до 1600 px, WebP q80; до 6 фото, до 12 МБ на исходник; `ads/YYYY/MM/<uuid>.webp`
- Рядом миниатюра 480×480 `<uuid>-t.webp` (~32 КБ против ~285 КБ) — её берут карточки, админка, превью (`thumbUrl`, у старых фото откат на полное)
- В объявление принимаются только фото из нашего хранилища
- Фото удалённых объявлений удаляются из S3 вместе с миниатюрами

### Ссылки и превью
- «Поделиться» и скопированная ссылка — с читаемым доменом `доска-квн.рф` (`prettyUrl`), а не punycode
- Превью ссылки на объявление: `og:image` — JPEG 1200×630 через `GET /ads/:id/og.jpg` (фото хранятся в WebP, ВКонтакте его в превью не показывает)
- «Назад» в шапках: если по сайту ещё не ходили (пришли по прямой ссылке) — на главную (`lib/nav.js`)
- Неверная ссылка — страницы «Объявление не найдено» и «Страница не найдена» с кнопкой к объявлениям
- Пока открыто любое окно, страница под ним не прокручивается (`lib/scrollLock.js`)

### SEO и правовое
- `/sitemap.xml` (главная, города, правила, одобренные объявления), `/robots.txt` (закрыты `/admin`, `/profile`, `/messages`, `/login`, `/favorites`, `/help`)
- `/terms`, `/privacy` (152-ФЗ): тексты по умолчанию — `lib/legal/terms.js`, `lib/legal/privacy.js`; правятся в админке (Настройки → «Правила и политика»), на сайте обновляются в течение минуты. Политика должна соответствовать коду: меняем сбор или хранение данных — правим текст
- Коды входа и закрытые/истёкшие сессии (в них IP и User-Agent) удаляются через 30 дней — раз в сутки, `AdLifecycleService.sweepTechnicalData`

### Защита от спама
- Глобально 300 запросов/мин, 5000/час, 50 000/сутки на ключ. Ключ — не IP (за прокси Amvera он у всех один, см. [API.md](API.md#rate-limit)): пользователь, e-mail для кодов входа, cookie гостя `gid`
- Точечно: коды входа 5/мин, 20/час, 50/сутки на почту и 500/час на весь сайт; объявления 5/час и 20/сутки; фото 30/час и 100/сутки; сообщения 20/мин; отзывы и жалобы 20/сутки; обращения 10/сутки
- Публичные ответы без приватных полей объявления (`publicAd`: телефон, служебный поиск, счётчик жалоб); ответы API сжимаются
- Сайт отдаёт защитные заголовки (`X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy`)
- Лимиты в памяти процесса — сбрасываются при рестарте

## 🔴 Технический долг

- **Схема через `prisma db push` при старте** (без `--accept-data-loss`): добавления применяются сами, изменение с потерей данных остановит старт API. Уникальное поле в существующей таблице тоже считается «потерей данных» — такие поля заводим в новой таблице (как `UserHandle`). Полноценные миграции отложены — нужен staging-Postgres
- **Настоящий IP клиента недоступен** (Amvera: перед ингрессом ещё прокси, все заголовки — 10.128.x). Лимиты переведены на пользователя / e-mail / cookie гостя. Спросить поддержку Amvera про передачу IP (proxy protocol); если включат — можно вернуть лимит по IP как второй ключ
- **Поиск по тексту** перебирает объявления: до десятков тысяч — быстро, дальше нужен триграммный индекс
- **Next 14 и NestJS 10** — оставшиеся уязвимости закрываются только переходом на Next 15 и Nest 11
- Остальное — в [AUDIT-2026-09-29.md](AUDIT-2026-09-29.md), раздел «Что осталось»
- ~~Осиротевшие фото в S3~~ — раз в сутки удаляются фото из `ads/` и `avatars/`, на которые ничего не ссылается и которые старше суток (`AdLifecycleService.sweepOrphanPhotos`)
- **Логи и мониторинг**: только console; ошибок в проде не видно
- **Счётчики непрочитанного и уведомлений — опросом** (5–60 с). При росте — WebSocket/SSE
- **Лимиты в памяти** — при нескольких инстансах API нужен Redis

## 🚀 Локальный запуск

⚠️ Двоеточие в имени папки `доска:квн` — разделитель `PATH`, поэтому `npm run dev` не находит `next`. Запускай напрямую:

```bash
# API
cd doska-kvn-api
npm install
DATABASE_URL=postgresql://… npx prisma db push --skip-generate
npm run start:dev

# Фронт
cd доска:квн
npm install
NEXT_PUBLIC_API_URL=http://localhost:3000/v1 node node_modules/next/dist/bin/next dev -p 3001
```

Вход через прод-API на localhost не работает (cookie на домене сайта): нужен локальный API с пустым `COOKIE_DOMAIN` и `COOKIE_SECURE=false`.
